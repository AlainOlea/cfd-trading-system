## Bugs identificados (esta sesión)

### 🔴 BUG #1 — Crypto sin Stop Loss
**Archivo**: `signals/alpaca_broker.py:357-399`
**Problema**: Las posiciones crypto se abren con MARKET + notional SIN bracket. Alpaca no permite brackets con notional.
**Causa de pérdida**: DOGE cayó a $0.0823 sin protección → -$10,353 unrealized.
**Fix**: Después del BUY, emitir 2 órdenes separadas (STOP SELL + LIMIT SELL). Si SL falla, safety close inmediato.
**Status**: ✅ IMPLEMENTADO (commit `896efec`)

### 🔴 BUG #2 — Acumulación por falta de cap acumulado
**Archivo**: `signals/alpaca_broker.py:38-45`
**Problema**: `MAX_POSITION_PCT = 0.05` aplica por trade, no por symbol. Bot hizo 18 BUYs DOGE en 18 horas.
**Causa de pérdida**: $66k acumulados en DOGE.
**Fix**: `CRYPTO_MAX_SINGLE = 3%`, `CRYPTO_MAX_AGGREGATE = 10%`, `MAX_CONCURRENT_POSITIONS = 3`.
**Status**: ✅ IMPLEMENTADO (commit `896efec`)

### 🔴 BUG #3 — `has_position()` permite acumulación
**Archivo**: `signals/alpaca_broker.py:288`
**Problema**: Check no bloquea crypto correctamente; el bot sigue añadiendo a posición existente.
**Fix**: `if self.has_position(alpaca_symbol): return "Already holding"`. Cooldown 4h adicional.
**Status**: ✅ IMPLEMENTADO (commit `896efec`)

### 🟡 BUG #4 — Ping-pong por señales opuestas 1d+1h
**Archivo**: `signals/pipeline.py:131` + `main.py:974`
**Problema**: `paper-trade` ejecutaba señales 1d y 1h del mismo ticker. El cluster AMZN del 1-Jun mostró 6 reversals en 6 min.
**Fix**: Añadido `--interval` flag. AHORA FUNCIONA (ver cambios implementados).
**Status**: ✅ IMPLEMENTADO

### 🟡 BUG #5 — Parser `get_trade_history` no calculaba P&L
**Archivo**: `signals/alpaca_broker.py:290-323` (viejo)
**Problema**: Asumía `parent.legs[]` que la API de Alpaca no devuelve.
**Fix**: Pairing heurístico MARKET ↔ LIMIT/STOP filled.
**Status**: ✅ IMPLEMENTADO

## Pendiente para la próxima sesión

### 1. Windows Task Scheduler ejecuta en fines de semana
- **Problema**: `StartWhenAvailable` causa que las tareas se ejecuten el domingo si la PC estuvo apagada
- **Fix**: Agregar market hours check en `.ps1` scripts o quitar `StartWhenAvailable`
- **Impacto**: 10 ejecuciones inútiles hoy (domingo), mismas señales repetidas

### 2. Señales duplicadas (mismo precio cada hora)
- **Problema**: yfinance no cambia fines de semana, `lookback = 5` genera misma señal
- **Fix**: Dedup con hash de últimas 5 filas + cooldown 1h
- **Estado**: Pendiente implementar

- **Error**: `stop_loss.stop_price must be <= base_price - 0.01`
- **Fix**: Re-validar SL/TP contra precio actual antes de submitir orden
